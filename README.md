# The Tech Briefing

Static-first information network at [thetechbriefing.com](https://thetechbriefing.com).

READ → UNDERSTAND → VERIFY → CONNECT → DISCOVER

This is not a generic news site and not an AI summary feed. Coverage is authored against sources, then generated as crawlable HTML.

The Lab is the retained portfolio and experiment layer. It is secondary to the network.

## Information model

Editorial objects live in `data/network.json`:

- SIGNAL
- BRIEFING
- TOPIC
- ENTITY
- SOURCE
- COLLECTION

Pages, `data/search-index.json`, `sitemap.xml`, `robots.txt`, and `feed.xml` are generated by:

```bash
python3 scripts/build_site.py
```

## Routes

| Path | Role |
| --- | --- |
| `/` | Current edition |
| `/briefings/` `/briefings/{slug}/` | Authored explainers |
| `/signals/` `/signals/{slug}/` | Curated, sourced observations |
| `/topics/` `/topics/{slug}/` | Persistent subjects |
| `/entities/` `/entities/{slug}/` | Companies, institutions, standards |
| `/collections/{slug}/` | Connected record sets |
| `/archive/` | Published records only |
| `/search/` | Client search over the generated index |
| `/about/` | Method and pipeline |
| `/lab/` | Portfolio, systems, reference, experiments |

Legacy `.html` paths redirect:

- `tech.html` → `/signals/`
- `lab.html` → `/lab/`
- `systems.html` → `/lab/systems/`
- `reference.html` → `/lab/reference/`
- `signal.html` → `/lab/experiments/xeno-signal/`

## RSS ingest is not the product

Pipeline:

SOURCES → INGEST → NORMALIZE → VALIDATE → DEDUPLICATE → CLASSIFY → EDITORIAL REVIEW → PUBLISH → CONNECT

`.github/scripts/update-tech-news.py` writes `data/ingest/rss-inbox.json`.

Every ingested record has `editorial_state: INBOX` and `publish: false`. Inbox items are never rendered as briefings or signals.

## Visual identity

Dark systems-console aesthetic: near-black ground, cyan-green accent, monospace metadata, thin technical borders. Editorial pages use rows, timelines, and metadata — not a card grid of headlines.

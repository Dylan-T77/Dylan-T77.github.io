# ᴅʏʟᴀɴ.exe // IT Systems Portfolio

Personal IT portfolio and technical project site for **Dylan Thiart**.

The website documents practical infrastructure work, lab environments, hardware, technical references, experiments and projects as they are built, tested, broken, fixed and documented.

## Design Language

The site uses a custom dark sci-fi / systems-interface aesthetic. This is **not a standard GitHub Pages theme**.

### Visual identity

- Near-black / dark interface background
- Cyan-green terminal accent
- Muted grey secondary text
- Monospace / technical typography
- Thin technical borders and HUD-style elements
- Grid-based layouts
- Subtle scanlines, glow and motion
- System status indicators
- Technical identifiers such as `SYS-01` and `PROJECT_001`
- Orbital / spacecraft-inspired graphics
- Information-dense layouts without unnecessary decoration

### Design philosophy

The website should feel like a **technical systems console** rather than a conventional corporate portfolio.

The visual language should remain consistent across new pages:

```text
BACKGROUND     near-black
PRIMARY        cyan / terminal green
SECONDARY      muted grey
TYPE           technical / monospace
SHAPE          angular / geometric
MOTION         subtle
DENSITY        information-rich
MOOD           spacecraft / systems console
```

The interface should remain futuristic, technical and clean without becoming visually noisy.

## Site Structure

- `index.html` - Main portfolio landing page
- `systems.html` - Hardware and operating systems inventory
- `lab.html` - Active labs and experiments
- `reference.html` - Technical command/reference library
- `signal.html` - Experimental XENO SIGNAL interactive spacecraft experience
- `css/style.css` - Core site styling
- `css/enhancements.css` - Additional visual and responsive enhancements
- `js/main.js` - Shared site interactions and effects

## Development Rules

1. Preserve the existing visual identity when adding pages or components.
2. Inspect existing files before making changes.
3. Prefer small, targeted changes over rewriting working pages.
4. Keep the XENO SIGNAL experiment isolated where practical.
5. Test responsive behavior in both desktop and mobile layouts.
6. Keep commit messages simple and descriptive, e.g. `Page update`, `Layout fix`, or `Reference update`.
7. Do not add unnecessary frameworks or dependencies for simple site functionality.
8. The portfolio should document real work and learning rather than presenting unfinished concepts as completed expertise.

# The Tech Briefing

Static-first information network at [thetechbriefing.com](https://thetechbriefing.com).

READ → UNDERSTAND → VERIFY → CONNECT → DISCOVER

This is not a generic news site and not an AI summary feed. Coverage is authored against sources, then generated as crawlable HTML.

The Lab is the retained portfolio and experiment layer. It is secondary to the network.

## Information model

Editorial objects live in `data/network.json`:

- SIGNAL
- BRIEFING
- TOPIC
- ENTITY
- SOURCE
- COLLECTION

Pages, `data/search-index.json`, `data/dashboard.json` (derived console dataset for the homepage), `data/asset-manifest.json` (content-hashed CSS/JS URLs), `sitemap.xml`, `robots.txt`, and `feed.xml` are generated by:

```bash
make build
# or: python3 scripts/build_site.py
```

CSS and JavaScript ship as content-hashed filenames (for example `/css/style.a1b2c3d4.css`) so GitHub Pages' 10-minute cache does not serve stale assets after a deploy. Source files remain unhashed under `css/` and `js/` for editing.

Derived JSON files (`dashboard.json`, `search-index.json`) are only rewritten when their semantic content changes — not on every build timestamp tick.

## Routes

| Path | Role |
| --- | --- |
| `/` | Current edition |
| `/briefings/` `/briefings/{slug}/` | Authored explainers |
| `/signals/` `/signals/{slug}/` | Curated, sourced observations |
| `/topics/` `/topics/{slug}/` | Persistent subjects |
| `/entities/` `/entities/{slug}/` | Companies, institutions, standards |
| `/collections/{slug}/` | Connected record sets |
| `/archive/` | Published records only |
| `/search/` | Client search over the generated index |
| `/about/` | Method and pipeline |
| `/lab/` | Portfolio, systems, reference, experiments |

Legacy `.html` paths redirect:

- `tech.html` → `/signals/`
- `lab.html` → `/lab/`
- `systems.html` → `/lab/systems/`
- `reference.html` → `/lab/reference/`
- `signal.html` → `/lab/experiments/xeno-signal/`

## RSS ingest is not the product

Pipeline:

SOURCES → INGEST → NORMALIZE → VALIDATE → DEDUPLICATE → CLASSIFY → EDITORIAL REVIEW → PUBLISH → CONNECT

`python3 scripts/run_ingest.py` writes `data/ingest/rss-inbox.json` and intelligence artifacts under `data/intelligence/`.

Every ingested record has `editorial_state: INBOX` and `publish: false`. Inbox items are never rendered as briefings or signals.

## Visual identity

Dark systems-console aesthetic: near-black ground, cyan-green accent, monospace metadata, thin technical borders. Editorial pages use rows, timelines, and metadata — not a card grid of headlines.

The homepage opens with the network console: an intelligence map of entity sites, relationship graph, and activity charts. Every value in it is derived from `data/network.json` at build time - records without a reliable geographic or relational basis are shown as unmapped rather than invented.

## Local preview

```bash
make dev
# builds the site, then serves at http://localhost:8080
```

Or step by step:

```bash
make build
python3 -m http.server 8080
```

Build layout lives under `scripts/lib/` (layout shell, HTML helpers, asset hashing). Page generators remain in `scripts/build_site.py`.
